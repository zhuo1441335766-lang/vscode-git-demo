# V0.2.0：UI 样板升级

状态：计划草案；不设承诺日期。前置基线：V0.1。

## 目标与范围

保留现有功能分组和业务行为，升级主框架、导航与一张充电功能样板页。先确认视觉和交互，再在后续版本推广。框架选型在方案比较后确定，暂不承诺更换 Tkinter。

## 工作项

| 标识 | 任务 | 验收条件 | GitHub Issue |
| --- | --- | --- | --- |
| UI-01 | 当前界面与操作路径盘点 | 有页面清单、基准截图和需保留的关键操作 | 待创建 |
| UI-02 | 视觉与布局方案 | 确认配色、字体、间距、导航、窗口与缩放策略 | 待创建 |
| UI-03 | 主框架与导航实现 | 原有模块可访问，当前模块清晰可见 | 待创建 |
| UI-04 | 充电样板页升级 | 状态分组清楚、原命令行为保持、效果确认 | 待创建 |
| UI-05 | 回归与发布归档 | 页面验证、相关设备验证、版本说明完成 | 待创建 |

UI-01 等为文档任务标识，不是 GitHub Issue 编号。创建真实 Issue 后替换链接。

## 验收材料

设计与截图按需存入 `docs/ui/v0.2.0/`，验证结果存入 `docs/acceptance/v0.2.0/`。记录系统显示缩放、分辨率、设备环境、提交号和结果。未连接设备的检查只标记为界面验证。

## 新增功能需求池

常用参数预设、组合测试场景、批量操作与结果导出仅为候选方向。各自先创建需求 Issue，确认价值、行为与验收方式，再决定归属版本，不混入本轮 UI 范围。
