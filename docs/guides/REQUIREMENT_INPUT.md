# 需求输入说明

## 怎么提供一条需求

直接在 GitHub 新建 UI/功能 Issue，或先在本地使用 [需求模板](../templates/REQUIREMENT.md)整理，再转成 Issue。GitHub Issue 作为任务状态的唯一来源，文档保存设计和验收细节。

至少写清：目标版本、功能模块、当前行为、期望行为、范围、验收条件。尚未确认的点标注“待确认”，不要把候选需求当作承诺。

## UI 输入示例

```text
标题：升级充电页面布局
目标版本：V0.2.0
模块：仪表/充电
目标：把状态选择与参数输入分组，操作反馈集中显示。
保留：现有状态选项、属性映射和操作能力。
材料：当前截图、期望布局草图；缺少时先产出设计稿。
验收：约定分辨率和缩放下文字完整；原按钮仍触发相同行为。
待确认：配色、最小窗口尺寸、是否允许新增 UI 依赖。
```

## 功能输入示例

```text
标题：新增常用充电场景预设
目标版本：待排期
场景：一次选择并应用一组常用测试参数。
输入：预设名称及参数清单。
输出：逐项执行结果与失败提示。
前提：目标平台、属性定义、执行顺序与恢复方式需确认。
验收：在指定台架执行后状态与参数一致；失败能定位到具体步骤。
```

## 进入开发前

- 范围和验收条件已确定；UI 有确认的设计方向，功能有输入/输出定义。
- 标注真实 Issue 链接、优先级、负责人和目标 Milestone。
- 需要设备的部分列出平台与验证方式。
- PR 附修改前后证据；未完成设备验收保留待验收状态。
